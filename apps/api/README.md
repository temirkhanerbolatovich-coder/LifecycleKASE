# API boundary

The internal `prepareSnapshotCandidate` reads a scheduled corporate action and Investor Registry wallet mappings through Prisma, checks the record-date grace window and expected Solana genesis hash, collects finalized Token-2022 holders, and produces canonical `snapshot-v2` bytes and SHA-256. It refuses unknown wallets, wallets verified after the record date, a stale instrument supply projection, unavailable slot block time, and an inactive action or instrument. A blocked but verified wallet remains in the ownership snapshot; payout eligibility is a separate decision.

`persistSnapshotCandidate` writes the canonical payload and investor/wallet/token-account rows in one serializable PostgreSQL transaction. It checks action and instrument versions, current wallet mappings and statuses, the record-date window, and the candidate hash; a compare-and-set increments the action version. The action stays `SCHEDULED` and the snapshot stays `PENDING_REGISTRATION` until a later signed on-chain registration is confirmed. A retry must resume that pending snapshot, not recapture holdings for the same action.

These are internal functions, not public HTTP endpoints. They do not authenticate an actor, prepare a wallet transaction, register an on-chain commitment, or claim an operational corporate-action flow. A future endpoint must enforce administrator authorization and audit the write before exposing them. Callers must provide a trusted current time, configured network/genesis hash, wallet network, and `SNAPSHOT_GRACE_SECONDS` (demo default: 300). Historical wallet status changes inside the snapshot window are not fully reconstructible from the current Wallet row; operational controls must freeze or audit registry changes around record dates.

Run `npm test --workspace @lifecycle-kase/api` from the repository root for fixture tests. With local PostgreSQL running and migrations applied, run `npm run test:api:database` for a real Prisma write/read/duplicate check; the script creates only isolated test records and removes them afterwards. A live mint and authenticated HTTP API are still pending. Administrator keys must never be stored in this service.
