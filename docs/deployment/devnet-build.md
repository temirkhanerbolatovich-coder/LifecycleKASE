# Isolated Devnet program build

Verified locally: 2026-10-01. This does not deploy or authorize a transaction.

## Profiles and identity checks

The default Rust profile keeps the existing disposable localnet program identity. The `devnet` Cargo feature selects the fresh public ID in the [approved plan](devnet-plan.json); `Anchor.toml` has independent localnet and Devnet mappings. Changing the Anchor provider cluster alone does **not** select the Cargo feature. Client/API fixture addresses remain localnet fixtures; production snapshot routes read the instrument's stored program ID rather than a hardcoded fixture address.

`scripts/check-program-identity.mjs` rejects drift between the conditional Rust declarations, Anchor mappings, plan and built Devnet IDL, checks the five implemented instructions, and validates the ELF artifact against the reviewed SHA-256 pin in the plan. The hash is from the observed feature-enabled build, not a reproducible-build attestation or a runtime/on-chain identity proof. A code/toolchain change that changes the hash must be rebuilt and reviewed before updating that pin; do not remove or auto-update it merely to bypass a mismatch.

## Build from PowerShell

Prerequisites: the reviewed non-root WSL toolchain and Windows Node.js available as `node.exe` in WSL. Adapt the checkout path on another machine.

```powershell
wsl -d Ubuntu -u lifecycle-dev -- bash -lc 'bash /mnt/c/Users/Админ/Documents/ChatGPT/LifecycleKASE/scripts/build-devnet-program.sh'
```

The script refuses root and an existing `generated/devnet-build` output path. Preserve/review or move prior non-secret build artifacts before rebuilding; it never deletes them for you. It builds using explicit Devnet cluster, Cargo feature and SBF v1.57, with outputs in an owner-only temporary Linux directory to avoid replacing root-owned DrvFS files. `--ignore-keys` skips the checkout's intentionally different localnet keypair check **only for this isolated build**. It does not bypass source/IDL/plan/hash checks or any on-chain authorization. No real Devnet private key is read or copied; any throwaway identity generated by SBF tooling is discarded with the temporary directory. Only the `.so` and public IDL are copied to ignored `generated/devnet-build/`. Localnet `target/deploy` and `target/idl` are not replaced.

Verify retained artifacts separately:

```powershell
node scripts/check-program-identity.mjs generated/devnet-build/lifecycle_kase.json generated/devnet-build/lifecycle_kase.so
```

## Validation and remaining gates

Both host Rust profiles passed 8 unit tests each, including the actual compiled `id()` selection. Rustfmt and Devnet Clippy passed; repository tests cover mismatched source/plan/IDL and binary hash pins. CI now tests both host Rust profiles. SBF/IDL build and retained-artifact identity/hash checks passed locally. The existing local-validator end-to-end integration test was not rerun during this change; Devnet runtime/finalized acceptance also remains pending. These checks do not prove issuance, transaction authority or settlement.

Backup, test funding, separate deployment approval, final genesis/ProgramData/upgrade-authority verification, wallet-signed initialization and chain/database reconciliation remain required. Never invoke `anchor deploy` against the default checkout keypair, never use `anchor keys sync` blindly across these conditional identities, and never put Devnet keys into `target/deploy` or Render to simplify tooling.
